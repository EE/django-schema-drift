## Serial primary keys

A database created before Django 4.1 keeps `serial` columns, which print as
`DEFAULT nextval(...)` against the models' `GENERATED BY DEFAULT AS IDENTITY`.
The report is true and the fix belongs to the database; a README note with the conversion SQL would help.

## Whole-table ignores

`SCHEMA_DRIFT_IGNORE` matches single lines,
so a table outside Django (`createcachetable`, PostGIS `spatial_ref_sys`) takes an entry per column and index.

## Locks held while the reference schema is built

The live snapshot's share locks last until the rollback,
so a `migrate` waiting on one holds up the queries queued behind it for the rest of the check.
Taking the snapshot in a transaction of its own would release them first.

## Indexes on materialized views

The index query does not filter on `relkind`, so such an index prints as `+` without its table.

## `check_migration_drift` on long histories

It compares the whole schema after every migration:
60 models and 300 migrations take 121 s, against 4.5 s for `migrate`.
Only migrations with `RunSQL`, `RunPython`, `SeparateDatabaseAndState` or custom operations, and the last one,
need comparing.

## Python 3.13

`requires-python` asks for it; the code runs on whatever Django 4.2 supports.

## Other databases and schemas

There is no `--database`, and only the current schema is compared.

## Collations

`db_collation` is a field option; `pg_attribute.attcollation` would add it to the column line.
